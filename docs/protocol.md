# Wire protocol

What vault-mcp sends and receives over stdio, captured from a real run on
2026-09-10 against the same two-note vault `demo.sh` builds (`alpha.md`
containing "first note about cats", `projects/beta.md` containing "cats and
dogs"). A file `secret.md` sat one level above the vault root for the
escape tests.

Every payload below is verbatim except where marked `[trimmed]` or noted
as pretty-printed. Pretty-printing changes whitespace only.

To reproduce, run the same pipeline `demo.sh` uses with these requests in
place of its single `tools/call`. Each request is one line on stdin, and
each reply is one line on stdout.

## Transport

- Newline-delimited JSON-RPC 2.0 on stdin and stdout.
- Notifications (no `id`) get no reply.
- Tool failures come back as a normal `result` with `isError: true`.
- Resource failures come back as a JSON-RPC `error` object.
- The SDK logs rejected arguments and failed calls to stderr, one line each.

## initialize

Request:

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"demo","version":"0"}}}
```

Reply:

```json
{"jsonrpc":"2.0","id":1,"result":{"capabilities":{"experimental":{},"prompts":{"listChanged":false},"resources":{"listChanged":false,"subscribe":false},"tools":{"listChanged":false}},"instructions":"Markdown notes vault at /private/var/folders/[trimmed]/tmp.R4s3mdTSiP","protocolVersion":"2025-06-18","serverInfo":{"name":"vault-mcp","version":""}}}
```

The client then sends `{"jsonrpc":"2.0","method":"notifications/initialized"}`
and gets nothing back.

## tools/list

Request:

```json
{"jsonrpc":"2.0","id":2,"method":"tools/list"}
```

Reply, pretty-printed. The schemas are generated by the SDK from the Python
signatures in `server.py`, so the `title` values are the SDK's own naming.

```json
{"jsonrpc": "2.0", "id": 2, "result": {"tools": [
  {"name": "search_notes",
   "description": "Case-insensitive substring search across all notes. Returns ranked hits with file, line, excerpt.",
   "inputSchema": {"type": "object", "title": "search_notesArguments",
     "properties": {"query": {"title": "Query", "type": "string"},
                    "limit": {"default": 20, "title": "Limit", "type": "integer"}},
     "required": ["query"]},
   "outputSchema": {"type": "object", "title": "search_notesOutput",
     "properties": {"result": {"title": "Result", "type": "array",
                               "items": {"additionalProperties": true, "type": "object"}}},
     "required": ["result"]}},
  {"name": "read_note",
   "description": "Read one note. `path` is relative to the vault root, e.g. 'projects/foo.md'.",
   "inputSchema": {"type": "object", "title": "read_noteArguments",
     "properties": {"path": {"title": "Path", "type": "string"}},
     "required": ["path"]},
   "outputSchema": {"type": "object", "title": "read_noteOutput",
     "properties": {"result": {"title": "Result", "type": "string"}},
     "required": ["result"]}},
  {"name": "list_notes",
   "description": "List notes, newest modified first. `folder` narrows to a subfolder.",
   "inputSchema": {"type": "object", "title": "list_notesArguments",
     "properties": {"folder": {"default": "", "title": "Folder", "type": "string"},
                    "limit": {"default": 100, "title": "Limit", "type": "integer"}}},
   "outputSchema": {"type": "object", "title": "list_notesOutput",
     "properties": {"result": {"title": "Result", "type": "array",
                               "items": {"additionalProperties": true, "type": "object"}}},
     "required": ["result"]}},
  {"name": "append_daily_note",
   "description": "Append a timestamped line to today's daily note (daily/YYYY-MM-DD.md), creating it if missing.",
   "inputSchema": {"type": "object", "title": "append_daily_noteArguments",
     "properties": {"text": {"title": "Text", "type": "string"}},
     "required": ["text"]},
   "outputSchema": {"type": "object", "title": "append_daily_noteDictOutput",
     "additionalProperties": {"anyOf": [{"type": "string"}, {"type": "boolean"}]}}}
]}}
```

Note the asymmetry in `outputSchema`: the three tools that return a `list`
or `str` have their value wrapped under a `result` key. `append_daily_note`
returns a `dict`, so its keys appear at the top level of `structuredContent`.

## tools/call

### search_notes

```json
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"search_notes","arguments":{"query":"cats"}}}
```

```json
{"jsonrpc":"2.0","id":2,"result":{"content":[{"text":"{\n  \"file\": \"alpha.md\",\n  \"line\": 3,\n  \"excerpt\": \"first note about cats\",\n  \"score\": 1\n}","type":"text"},{"text":"{\n  \"file\": \"projects/beta.md\",\n  \"line\": 3,\n  \"excerpt\": \"cats and dogs\",\n  \"score\": 1\n}","type":"text"}],"isError":false,"structuredContent":{"result":[{"file":"alpha.md","line":3,"excerpt":"first note about cats","score":1},{"file":"projects/beta.md","line":3,"excerpt":"cats and dogs","score":1}]}}}
```

The SDK emits one text block per list element in `content`, each
pretty-printed JSON, and the whole list once more in `structuredContent`.

### read_note

```json
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"read_note","arguments":{"path":"projects/beta.md"}}}
```

```json
{"jsonrpc":"2.0","id":3,"result":{"content":[{"text":"# Beta\n\ncats and dogs\n","type":"text"}],"isError":false,"structuredContent":{"result":"# Beta\n\ncats and dogs\n"}}}
```

### read_note, path outside the vault

```json
{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"read_note","arguments":{"path":"../secret.md"}}}
```

```json
{"jsonrpc":"2.0","id":4,"result":{"content":[{"text":"Error executing tool read_note: path escapes vault root: ../secret.md","type":"text"}],"isError":true}}
```

The message after `Error executing tool read_note:` is the `ToolError`
text raised in `VaultServer.read_note`. A missing file gives the same shape
with the path as the message. On stderr the SDK logs:

```
Tool 'read_note' failed: 'Error executing tool read_note: path escapes vault root: ../secret.md'
```

### list_notes

```json
{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"list_notes","arguments":{"folder":"projects"}}}
```

```json
{"jsonrpc":"2.0","id":5,"result":{"content":[{"text":"{\n  \"path\": \"projects/beta.md\",\n  \"modified\": \"2026-09-10T11:07:57\"\n}","type":"text"}],"isError":false,"structuredContent":{"result":[{"path":"projects/beta.md","modified":"2026-09-10T11:07:57"}]}}}
```

### append_daily_note

```json
{"jsonrpc":"2.0","id":6,"method":"tools/call","params":{"name":"append_daily_note","arguments":{"text":"called the dentist"}}}
```

```json
{"jsonrpc":"2.0","id":6,"result":{"content":[{"text":"{\n  \"path\": \"daily/2026-09-10.md\",\n  \"created\": true,\n  \"line\": \"- 11:08 called the dentist\"\n}","type":"text"}],"isError":false,"structuredContent":{"path":"daily/2026-09-10.md","created":true,"line":"- 11:08 called the dentist"}}}
```

### Missing required argument

```json
{"jsonrpc":"2.0","id":12,"method":"tools/call","params":{"name":"search_notes","arguments":{}}}
```

```json
{"jsonrpc":"2.0","id":12,"result":{"content":[{"text":"Error executing tool search_notes: 1 validation error for search_notesArguments\nquery\n  Field required [type=missing, input_value={}, input_type=dict]\n    For further information visit https://errors.pydantic.dev/2.13/v/missing","type":"text"}],"isError":true}}
```

Argument validation is done by the SDK with pydantic before the tool
method runs. Stderr gets `Tool 'search_notes' rejected arguments: ['query']`.

## Resources

URI scheme: `note://<vault-relative path>`, with forward slashes and no
leading slash. The path is the same string `list_notes` returns in `path`.

### resources/list

```json
{"jsonrpc":"2.0","id":7,"method":"resources/list"}
```

```json
{"jsonrpc":"2.0","id":7,"result":{"resources":[{"mimeType":"text/markdown","name":"alpha.md","uri":"note://alpha.md"},{"mimeType":"text/markdown","name":"daily/2026-09-10.md","uri":"note://daily/2026-09-10.md"},{"mimeType":"text/markdown","name":"projects/beta.md","uri":"note://projects/beta.md"}]}}
```

`daily/2026-09-10.md` appears because the `append_daily_note` call above
created it. The list is rebuilt from disk on every request and sorted by
path.

### resources/templates/list

```json
{"jsonrpc":"2.0","id":8,"method":"resources/templates/list"}
```

```json
{"jsonrpc":"2.0","id":8,"result":{"resourceTemplates":[{"description":"","mimeType":"text/markdown","name":"note_resource","uriTemplate":"note://{+path}"}]}}
```

`{+path}` is RFC 6570 reserved expansion, which is what lets the parameter
contain slashes.

### resources/read

```json
{"jsonrpc":"2.0","id":9,"method":"resources/read","params":{"uri":"note://projects/beta.md"}}
```

```json
{"jsonrpc":"2.0","id":9,"result":{"contents":[{"mimeType":"text/markdown","text":"# Beta\n\ncats and dogs\n","uri":"note://projects/beta.md"}]}}
```

### resources/read, path outside the vault

```json
{"jsonrpc":"2.0","id":10,"method":"resources/read","params":{"uri":"note://../secret.md"}}
```

```json
{"jsonrpc":"2.0","id":10,"error":{"code":-32602,"message":"Unknown resource: note://../secret.md","data":{"uri":"note://../secret.md"}}}
```

This one is rejected by the SDK before `note_resource` runs: its template
matcher refuses `..` segments and absolute paths by default, so the URI
matches no resource and no template. The vault's own check is still there
behind it.

### resources/read, missing note

```json
{"jsonrpc":"2.0","id":11,"method":"resources/read","params":{"uri":"note://missing.md"}}
```

```json
{"jsonrpc":"2.0","id":11,"error":{"code":-32603,"message":"missing.md","data":{"uri":"note://missing.md"}}}
```

Here the template did match, `note_resource` raised `ResourceError`, and the
SDK turned that into an internal error whose message is the exception text.
